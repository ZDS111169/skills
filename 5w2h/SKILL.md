# 5W2H

把一件事拆成七问，写成可执行的问题陈述或行动计划。不是调研长文（那用 `/stormx`）。

## 何时触发

命中任一句即跑**完整 5W2H**（七问全答 + 合成陈述）：

- `用5W2H分析【主题/问题】`
- `5W2H【主题】` / `五何两H【主题】`
- `/5w2h`（有主题则直接跑；无主题先问一句）
- `把【xx】写成问题陈述` / `立项澄清一下【xx】`

若用户只要其中几问（例如「只要 How 和 How much」）→ 只答点名项。

## 七问（必须逐项回答）

对【对象】（问题 / 项目 / 流程 / 决策均可）：

| 维度 | 英文 | 要答清 |
|------|------|--------|
| 做什么 | **What** | 对象是什么、发生了什么、要交付什么；避免空话 |
| 为什么 | **Why** | 目的、动机、不做的后果 |
| 谁 | **Who** | 责任人、干系人、受益/受害方 |
| 何时 | **When** | 时间点、期限、频率、里程碑 |
| 何处 | **Where** | 地点、系统、模块、组织范围 |
| 怎么做 | **How** | 方法、步骤、工具、约束 |
| 多少 | **How much** | 成本、工时、数量、影响面、优先级量级 |

规则：

1. 未知项写 `未知`，并给「如何补齐」的下一问（不要编造数字）。
2. 每项用短句 + 必要子弹；禁止大段注水。
3. 七问答完后，必须输出下方「合成陈述」和「缺口清单」。

## 输出模板

```markdown
## 5W2H — 【对象】

### What
…

### Why
…

### Who
…

### When
…

### Where
…

### How

### How much
…

## 合成问题/项目陈述（一段话）
（把七问收成 3–6 句可执行陈述，具体到人/时/地/量）

## 缺口清单
| 缺口 | 为何挡事 | 建议如何补 |
|------|----------|------------|
| … | … | … |

## 下一步（可选 1–3 条）
- …
```

## 使用场景切换

| 场景 | 侧重点 |
|------|--------|
| **定义问题** | What/When/Where/How much 要具体；Why 写清痛点 |
| **立项/计划** | Who/When/How/How much 要可验收 |
| **复盘** | What 实际发生 vs 原计划；How much 写偏差 |

## Do not

- 不要和 STORMX 十步混跑，除非用户同时点名两个 skill
- 不要伪造成本或工期；未知就标未知
